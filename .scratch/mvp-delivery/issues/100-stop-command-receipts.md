# 100 · 停止请求对账与目标保护

Status: resolved
Type: task
Blocked by: 99

## 直接证据

隔离Host在空闲会话受理key=old-idle-stop后启动真实ACP /wait任务，再次提交旧停止请求，实际把新Run取消。当前接口忽略key，不能防止丢失响应后的旧请求作用于后续任务。

## 验收

- 停止支持可选key与目标runId；同键同参数仅返回原受理事实，不再次发送停止信号；不同参数冲突。
- 首次请求目标过期时不停止其他Run。空闲停止也保留受理身份，重启仍可对账。
- 会话停止投影与回执原子提交，失败不发布假受理。受理与Agent实际终止分别展示，不自动重放。
- 正式停止按钮绑定当前活跃Run，兼容旧Host和旧无body/无key调用。
- 真实Host、存储故障、桌面及手机权限验证，中文文档和SVG更新并提交。

## Answer

停止请求增加可选key/runId及实际Rust请求/响应共享契约。会话门内先查持久受理，再验证目标；同键不重投信号，不同参数冲突，首次过期目标不作用于其他Run。空闲停止也保存受理，停止投影/事件/回执原子提交。正式桌面/手机按钮在同一Run持续使用同key，目标选择排除排队、撤回和已结束记录；旧Host、无key及空body调用兼容。

直接验证旧空闲停止在Host重启后重试不取消新/wait任务，正确目标可以停止，过期目标拒绝，重复请求不追加事件；SQLite注入验证停止投影及回执一起回滚。客户端目标选择测试覆盖后续排队/撤回，桌面与HTTPS手机捕获实际key/runId，viewer与未授权目录不能对账。

最终验证：60项Node/SDK、workspace Rust（Workbench51项、存储7项）、44项Host、恢复、严格Clippy及格式通过；桌面70.7秒、HTTPS23.6秒通过。834.77MiB包与仓库外冒烟通过，Host SHA256为`390f8945aeac1cc60ea3790716ad1180c750b8698b2ac3c9ea64219ceeb901ef`。中文说明及已渲染核对的SVG见 `docs/stop-command-receipts.md`。

用户Host未重启，按公开status字段核对5个会话均idle、队列为空且服务健康。整体原型验收未结束；同轮直接确认的队列撤回重复冲突及产物重复保存分别交由101/102继续，14和52不提前关闭。
