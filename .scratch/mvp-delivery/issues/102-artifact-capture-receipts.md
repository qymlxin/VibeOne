# 102 · 产物保存回执与原始快照保护

Status: resolved
Type: task
Blocked by: 101

## 直接证据

隔离Host对相同会话/文本路径/key连续保存快照，实际生成不同产物ID。响应丢失后重试会重复占用产物配额，且可能读到已经变化的文件。

## 验收

- 文本产物保存支持可选key，同键同路径返回第一次保存的ID和内容，不重复读取/占用配额；不同请求冲突。
- 产物、事件和回执原子提交，重启可对账，失败不发布假快照；文件范围、类型和容量限制保持。
- 正式保存入口保留未知结果的请求身份，状态/错误可读，不自动重放；设备权限保持。
- 首次快照关联最近实际开始的Run，不归属尚未执行或已撤回的队列项；重试保留原关联。
- 真实Host、文件变化/删除、存储故障、桌面/手机与契约验证，更新中文文档及需要的SVG，单独提交。

## Answer

保存请求与成功回执采用实际Rust结构并生成共享Schema/TypeScript，客户端统一用captureArtifact构造命令。可选key按会话隔离、参数指纹冲突校验；产物、事件和只含指纹/产物ID的私有回执同事务，提交成功才发布内存。相同请求重取原ID、内容、时间与执行关联，文件变化/删除、配额满或Host重启后不重读源文件，也不重复占用配额。旧无key行为保留。

正式保存入口由会话级控制器保留未知请求，切换文件、关闭预览、切到其他面板再返回仍可手动同键重试；不自动重放，未确认时禁止新路径覆盖原身份。中文状态与独立失败提示、原目标及显式关闭齐全，手机保存/重试/关闭均验证44px。首次保存关联最近有startedAt的执行；新增单元用例先复现错误关联撤回队列项，再修复并由真实手机流程覆盖，重试不重写历史归属。

验证：60项Node/SDK、workspace Rust（Workbench53项、存储9项）、46项Host、恢复、严格Clippy及格式通过。实际SQLite故障验证事务回滚；并发、重启、内容变化/删除、配额和设备权限通过。最终桌面71.7秒、HTTPS手机23.9秒通过，亮暗/手机截图和SVG已渲染查看。834.97MiB桌面包及包外冒烟通过，Host SHA256为`00a75fcd7f79d492395e5bc49dc8e5ae03d88dabfdcbdc2ec6fc8878c9c207df`。
