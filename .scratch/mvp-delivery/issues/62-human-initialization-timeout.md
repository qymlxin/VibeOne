# 62 · 初始化阶段的人工等待时限

Status: resolved
Type: task

## 待验证边界

AgentSession连接整体目前有30秒就绪超时，权限/补充输入各自允许600秒。客户端已经支持会话创建完成前的request-scoped人工请求，需要确认正常人工作答是否会被整体启动时限误判为卡死。当前仅有快速作答的正向用例，不能据此证明长等待成立。

## 范围与验收

- 使用已有stdio演示进程的--input-before-session和可控时钟复现：请求进入等待后推进超过30秒，再回答；记录实际结果，不预先假定是哪层超时。
- 若复现，修复初始化等待预算，保留无人工作答时的正常卡死超时，不给所有连接无条件延长等待。
- 人工请求仍受自己的时限约束；取消可中断初始化，旧请求失效，相关进程得到清理。
- 核对SDK内部请求时限和本地外层预算，补正向/反向回归及中文文档。此票不包含登录用户账号或解锁设备。

## Answer

真实stdio回归先复现：发布会话创建前的输入请求，推进45秒后，连接提前返回“ACP v2 初始化失败或超时”。检查锁定SDK 5.0.0的请求/会话实现后，定位为本地30秒外层就绪超时。

已将累计30秒工作预算与每个600秒人工请求分开。成功发布的问题暂停工作计时，最后一个重叠问题结束后恢复剩余时间；请求发布和回执IO仍计时。启动取消/失败同时清除旧请求，并交由SDK清理连接及进程。不改变生产600秒时限，不放宽所有初始化。

验证：客户端13项（4个预算边界、9个真实stdio集成）和Clippy通过；Rust工作区、Host12项及SQLite恢复通过。取消测试确认真实Node父子进程均已退出。图已通过浏览器渲染核对，说明见docs/structured-input.md。权限Schema要求sessionId，故未伪造无会话权限请求。

首次Host总回归受到另一个并发cargo构建改写同一可执行文件影响，出现macOS spawn -88；固定构建产物后的完整12项重新通过，原失败记录未当作通过依据。

交付：真实Codex ACP v2握手/消息返回end_turn；桌面调试包重新生成，包外副本的HTTPS网页、Worker上下文、插件Provider、历史、两个桥接器握手及CLI验证通过。包内Host哈希记录在docs/prototype-audit.md。原生锁屏及Claude认证缺口保持原记录。
