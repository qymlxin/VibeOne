# 97 · 会话创建幂等与丢失回执恢复

Status: resolved
Type: task
Blocked by: 96

## 发现的缺口

96审计14的命令幂等条目时，以隔离Host两次提交相同provider/workspace/key，实际返回不同会话，快照出现两个会话。当前创建请求没有key字段，不能依赖前端按钮禁用作为对账保证。

## 目标与验收

- 创建请求支持可选幂等key，兼容无key的旧调用；共享契约和正式创建入口接入。
- 同key同输入只创建一个会话及默认项目，不同输入明确冲突。
- 创建身份与持久回执原子保存，存储失败不返回假成功；重启后重复请求得到原身份。
- 已固定的Profile及工作区身份不因重试改投；查询受既有设备权限约束。
- 页面在结果未确认时保留请求身份，不自动重复创建；输入变化代表新意图。
- 真实Host/存储/正式页面验证，中文文档及需要的SVG更新，独立提交。

## Answer

创建请求与共享构造器增加可选key，Host在目录串行门内以参数指纹对账；同键返回原会话，不重选Profile和默认目录，不同参数409。SQLite在同一事务写入创建投影、事件和私有回执，重启仍可重复查询。正式表单保留未确认提交身份，不自动重发，保留无key与旧Host兼容。

直接验证：8个并发请求只有一个会话/默认项目，重启返回原ID，Profile删除后仍返回原身份；回执写入失败原子回滚，Workbench存储失败不发布回执且删除空托管目录；桌面真实丢失响应后同键手动重试无重复；HTTPS操作设备可以对账，viewer与未授权目录不能绕过权限。权限夹具使用授权列表返回的规范路径，与正式手机表单一致。

最终检查：59项Node/SDK，workspace Rust（Workbench50项及新增失败清理用例单独通过），42项Host、恢复、Clippy与格式检查通过；桌面70.3秒，HTTPS补充权限回归23.6秒通过。834.58MiB桌面包及仓库外冒烟通过，Host SHA256为`220e1fd55f81b31e1b2dc4012eb50222e9a8672b687258de4016cb4e72c2af5a`。中文说明与已渲染核对的SVG见 `docs/session-creation-idempotency.md`。实际用户Host健康、5会话、无活跃任务/队列，未重启；原生/物理设备验收继续保留，14仍待全部原始契约复核。
