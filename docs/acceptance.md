# 主要功能版体验与验收

本版把桌面、独立 Host、插件和手机控制接入真实业务链路。交互细节继续后置。自动化验证使用独立临时数据目录，不停止用户现有 Host，也不修改用户工程、认证或全局工具配置。

## 启动与升级

源码运行：`npm ci && npm run desktop`。打包：`npm run desktop:bundle`；生成 `apps/desktop/src-tauri/target/debug/bundle/macos/VibeOne.app`。

退出旧桌面进程，再打开新版应用。关闭窗口会隐藏到托盘；托盘提供“打开”“退出桌面（主机继续运行）”“停止所有执行并退出”。如果提示主机版本较旧，先结束执行，在设置中重启主机。旧内存版会先导出历史，已有 SQLite 版直接执行数据库迁移。

本版 Host 能力标识为 `apiVersion: 3`。桌面 IPC 负责主机生命周期、目录选择、证书导出和系统通知，业务通过 HTTP/WS 进入 Host。

运行需要本机 Node.js 22+。本地包携带 Host、手机页面、插件运行时、SDK 和示例插件；Codex、Claude Code 的接入程序与认证仍由本机环境提供，可通过 Agent Profile 指定启动程序和参数。正式签名、公证、跨机器依赖分发不在本轮自动验收结论内。

## 统一数据目录与项目

桌面默认使用 `~/.vibeone`（主目录不可写时自动使用现有可写的 `~/.config/vibeone` 或 `~/.local/share/vibeone`，设置显示实际路径）：SQLite 保存统一会话/配置/插件索引，`projects/project-<id>/` 保存未选择目录时自动创建的项目文件。选择已有工作区时仅关联原目录，不复制或移动工程。新建会话不要求先选目录；可在工作区列表中复用先前项目。远程设备仍只能选择已授权工作区。

旧桌面数据目录在 Host 空闲时自动停止并原子迁移，旧路径保留为兼容别名，避免已有插件固定路径失效。活动执行期间继续附着旧 Host，设置中提示待迁移；目标目录已有数据时不覆盖或合并。

- [ ] 不选择目录，创建会话并发送；确认工作区位于 `~/.vibeone/projects/`。
- [ ] 再建一个默认项目，确认目录独立；选择上一个目录可共享项目文件。
- [ ] 旧历史会话点击“在新上下文继续”，确认历史保留、新消息可发送；旧消息不会自动发送给 Agent。

## 功能与验证状态

| 功能 | 实现与自动验证 | 仍需人工验证 |
| --- | --- | --- |
| 会话与配置 | 创建空会话、首条消息启动、标题搜索、重命名、归档；创建时固定 Profile 修订及插件 Provider 代次 | 真实工程中的日常操作 |
| 对话 | ACP v2 接受回执与独立完成状态；流式回复、思考摘要、Markdown、工具输出、计划、只读终端输出与用量投影 | 各真实工具实际提供的消息类型；工具不提供思考摘要时只显示等待状态 |
| 执行队列 | 一个会话一个活动 Run；最多 20 条队列；正常完成后继续；撤回、幂等重试、暂停与显式恢复 | 长时间运行和大工程负载 |
| 工作区冲突 | 同一 Git Worktree 的会话共享执行锁；冲突拒绝，独立 Worktree 可分别执行 | 特殊 Git 布局和真实并发写入工具 |
| 取消 | 取消请求、队列暂停、宽限期、关闭 Agent 连接及 SDK 进程组清理；自动测试验证拒绝响应的假 Agent 与真实子进程 | 不响应取消的真实工具及其复杂子进程树 |
| 审批 | 原始选项、有效期、Run 归属、唯一决定；同决定重试幂等，不同决定冲突；决策与投递分开保存 | 真实工具触发审批的完整操作 |
| 补充输入 | ACP `elicitation/create`；表单 JSON Schema 校验；接受、拒绝、取消；与权限审批分开处理 | 真实工具的复杂表单及 URL 授权流程 |
| 恢复 | SQLite 迁移、版本不兼容诊断、SIGKILL 恢复、旧审批失效、不自动重放、存储失败停止接收执行 | 系统断电和磁盘异常 |
| 工作区文件 | 导入、列表、目录与文本读取；拒绝父路径、绝对路径和符号链接越界；使用能力目录打开文件 | Windows/Linux 的文件系统差异 |
| 引用与产物 | 输入可引用工作区文本；受理和执行前重新校验；文本快照产物关联最近 Run，后续文件变化不改变已保存内容 | 实际工程的文件引用与产物整理 |
| Git 变更 | 未暂存、已暂存、未跟踪、分支、采集时间；只读 diff；二进制与内容截断提示 | 大仓库、子模块、复杂重命名 |
| 插件 | 目录检查、权限和范围授权、配置校验、安装、更新、停用、重新启用；候选失败保留旧版本；动态 React 面板和 Worker 反向调用 | 自编第三方插件和长时间热更新 |
| 插件业务消费 | 声明式 Agent Provider 实际创建会话；已有会话保留代次；执行结束和待处理事件交给通知扩展，扩展失败不改变执行结果 | 真实通知渠道实现 |
| 插件作者工具 | JS/TS/TSX 构建为 ESM；创建模板、清单检查、打包；共享 React、React DOM 和 SDK | 不同依赖组合和第三方作者体验 |
| 诊断 | 导出只包含允许列表中的计数、状态和版本；测试确认不包含路径、消息、令牌 | 用户实际故障案例 |
| 手机传输 | 本机私有地址 HTTPS/WSS；生成独立 CA 与服务器证书；Node 客户端使用此 CA 校验 TLS | iOS/Android 安装并信任证书，以及真实局域网、防火墙与可信网络连通性 |
| 手机身份 | 短期配对码、电脑确认、90 天设备凭据、工作区范围、viewer/approver/operator、过期和撤销检查 | 真实设备的长期凭据保留 |
| 手机操作 | 移动尺寸浏览器经过真实 HTTPS、Secure/HttpOnly Cookie 和 WSS，完成新建会话、发送、审批、停止；越权拒绝、撤销退出 | 真机触控、切后台、锁屏及弱网 |
| 桌面壳 | Tauri 编译、托盘、隐藏/退出/停止入口、主机升级、证书导出、本机通知接线 | 托盘与系统通知权限弹窗的真实 macOS 操作 |

真实 Codex 隔离烟测已通过；Claude Code 当前返回 `Authentication required`，需要在用户本机完成工具认证后再验。演示 Agent、浏览器移动视口和 Node TLS 校验均不替代真实工具审批或物理手机验收。

## 手机连接步骤

1. 桌面设置中选择本机局域网或已有可信网络 IP，开启 HTTPS 手机入口。不会监听通配地址、映射路由器端口或建立公网 Relay。
2. 导出 `VibeOne-Root-CA.crt`，通过用户自己的可信方式传到手机，按手机系统流程安装并信任此 CA。证书只包含公钥，私钥保留在 Host 数据目录。更换监听 IP 会重新签发证书，需重新检查信任。
3. 手机打开设置页显示的 HTTPS 地址或扫描二维码；在电脑生成 5 分钟配对码，手机填写设备名称和配对码。
4. 在电脑核对请求并选择工作区和权限。viewer 只查看；approver 可查看及审批；operator 可查看、发送、取消、处理补充输入和审批。手机不能管理插件、设备授权或停止整个 Host。
5. 手机凭据使用 Secure、HttpOnly、SameSite=Strict Cookie，不放进 URL；服务端只保存凭据哈希。撤销后 HTTP 请求拒绝，已有 WSS 连接关闭。

- [ ] iOS 真机 CA 信任、HTTPS/WSS 连通。
- [ ] Android 真机 CA 信任、HTTPS/WSS 连通。
- [ ] 手机 viewer 越权操作被拒绝，换 operator 后可发送与审批。
- [ ] 电脑和手机同时处理同一审批，只接受一个决定。
- [ ] 手机断网时只保留草稿，禁止提交审批；网络恢复后以 Host 快照恢复状态。
- [ ] 撤销设备后，已打开的手机页面退出授权状态。
- [ ] 切后台、锁屏、Wi-Fi 切换、Host 重启后的实际表现。

浏览器自动化对手机页面使用测试环境的证书忽略选项；另一条 HTTPS 测试使用生成的 CA 做真实证书校验。二者不能证明手机操作系统已经信任证书。真机项目保持待验状态。

## 当前明确边界

- 重启后的历史默认暂停执行，可点击“在新上下文继续”在同一会话发送；暂停队列可以明确选择“在新 Agent 上下文执行”，保留旧历史，但不恢复旧工具进程或隐藏思考状态。不同连接的上游消息 ID 已隔离，避免复用 ID 覆盖历史。
- 当前会话投影保留最近 128 条消息，单条最多 65,536 字符；持久事件日志另行保存。长历史分页和完整历史重建尚未提供，不能把当前列表当作无限历史。
- 队列容量 20、会话 Run 上限 1000、未归档会话上限 128；文本引用每次最多 5 个且每个 32 KiB；文本预览/产物最多 256 KiB，截断会明确显示。暂不上传图片和二进制附件。
- 事件日志提供稳定 ID、游标和分页查询；桌面与手机当前依靠 WS 通知后获取快照恢复，尚未使用增量 reducer 或提供事件日志保留策略。
- 审批投递状态表示本地 ACP 响应路径的状态，不能证明 Agent 已执行工具。投递不确定时不自动重放批准。通知使用事务 outbox、稳定 eventId、最多三次退避重试，旧待处理通知在重启后丢弃；插件对外部副作用需按 eventId 幂等。
- 插件是可信本机代码，Node 原生 API 不属于 Host 文件 API 的安全边界。当前插件采用单文件 App ESM、自包含依赖、严格 API 范围；跨插件依赖解析、市场、签名与自动进程重启未开放。自动重启预算为 0，失败由管理页人工重新启用。
- 通知在桌面进程运行时可用，窗口可以隐藏；彻底退出桌面后 Host 继续工作，但内置桌面通知监听不保活。手机网页没有锁屏 Web Push 保证。
- 真实工具认证、真实审批、真机网络与证书、桌面托盘/系统通知、跨平台和正式签名公证仍需上述人工验收，不将这些项目写成已通过。

## 自动验证入口

```sh
npm run check
npm run desktop:test
npm run remote:test
cargo clippy --workspace --all-targets -- -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

`npm run check` 包含插件 SDK/运行时、作者工具、ACP、存储、Host、队列、权限、工作区、插件业务消费和崩溃恢复。桌面与手机浏览器测试使用本机 Chrome；可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定测试浏览器。

真实模型验收单独运行 `npm run agent:smoke -- codex claude`，使用本机已有认证和临时工作区，不放进默认测试套件。
