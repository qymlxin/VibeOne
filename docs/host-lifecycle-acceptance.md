# 独立 Host 生命周期验收

本次核对07的服务端验收，不把它替代17/52的真实原生窗口、托盘和退出交互。测试全部运行在隔离数据目录，不使用用户的实际Host或会话。

| 原始验收 | 当前实现与直接证据 |
| --- | --- |
| 单实例、启动/附着、状态查询 | 相同目录第二次启动非零退出；原发现文件字节不变，原PID仍运行，原凭据仍可查询真实快照；停止后可重新启动 |
| 仅本机、受限发现文件、认证与Origin | URL为127.0.0.1；macOS目录/发现文件没有组或其他用户权限；无凭据401，不可信Origin403 |
| 客户端断开不停止Agent | 使用实际WS升级和第一帧凭据认证，收到ready后开始任务并断开TCP；HTTP仍可查询相同Run身份，Agent子进程仍活着 |
| 明确停止清理与退出 | 活跃ACP夹具派生真实子进程；请求停止后Host正常退出0，ACP父进程及子进程均退出，发现文件删除，实例锁释放 |
| 历史与中断 | 相同目录重新启动取得新凭据，保留消息，未结束会话/Run为interrupted，旧审批为空，不自动重新执行 |

实现入口是 `server.rs::serve`、`socket_loop`、`Workbench::stop` 和Agent客户端的进程组清理；新测试为 `tests/host-lifecycle.test.mjs`，已有 `tests/workbench.test.mjs` 继续覆盖真实ACP审批、取消与快照。测试已纳入 `npm run host:test`，后续完整check会执行。

Windows不运行本次Unix进程树用例，不能据本机结果声称跨平台实机全部通过。原生窗口隐藏/退出后保活仍需要原生验收；物理手机和真实Claude也继续保留。服务端验收通过不代表整个原型目标已完成。

同轮API审计另外确认过会话创建携带相同key仍生成两个会话，该缺口的后续修复与验证见[会话创建与重试对账](session-creation-idempotency.md)。14仍需按原始全部验收逐项核对，不能据一项修复提前关闭。
