# VibeOne UI 与交互设计

版本：0.3 · 2026-11-05。当前紧凑布局、中性配色和亮暗模式以 [交互原型](../prototype/README.md) 为视觉基线。文字、记录与设备均为示例。

## 1. 设计目标

用户应能直接回答：当前在哪里运行、Agent 正在做什么、是否需要我处理、操作是否生效、代码改了什么。桌面适合持续工作和检查，手机适合快速查看、指令与审批；不把整个桌面压缩到手机。

整体采用安静的中性工作台，支持亮色、暗色和跟随系统。导航选中使用中性表面，主操作使用石墨色，避免大面积装饰性色块。橙色表示等待人工，红色表示失败，绿色表示明确完成，运行状态使用克制的蓝灰色；每种状态同时包含文字和图标，避免只靠颜色区分。审批保留明确的操作边界，减少嵌套卡片、阴影和宣传式文案。

## 2. 信息架构

| 桌面入口 | 内容 | 手机入口 |
| --- | --- | --- |
| 工作区 | 会话列表、任务、文件和变更 | 会话 |
| 待处理 | 工具审批、补充信息 | 审批，显示 pending 数 |
| 插件 | 安装、配置、运行状态 | 设置内查看，安装管理首版以桌面为主 |
| 设备与连接 | 配对、角色、在线、撤销 | 主机与设置 |
| 设置与诊断 | Agent、外观、日志 | 设置 |

顶部固定显示当前 Host 与连接状态。运行中的会话数、待处理数来自真实投影，不显示虚构进度百分比。路径、进程 ID、协议等实现细节只在检查区或诊断中出现。

## 3. 桌面工作台

### 3.1 布局

采用应用导航、会话列表、弹性主时间线与右侧检查区。聚焦布局将会话列表放入约 188px 的导航栏；并列布局使用约 174px 导航、210px 会话列表和 300px 检查区。实际宽度随断点调整，空间不足先把检查区变成抽屉，再折叠会话列表。

桌面参考稿为 1440px 宽；实现建议断点：≥1280 四区，960–1279 导航缩窄且检查区抽屉化，720–959 会话列表按需切换，<720 使用移动布局。断点是布局策略，需通过内容压力测试微调。

顶部显示工作区、分支、Agent 和能力入口；主区底部为任务输入。会话切换保留草稿、滚动位置和展开状态。拖动分隔条可调整区域，提供恢复默认布局，不能把主阅读区拖到不可用。

### 3.2 时间线

用户消息、Agent 内容、工具与审批拥有清晰的类型标题。工具默认显示名称、摘要和状态，原始输入/输出按需展开。执行计划只显示上游报告的项目；未知思考内容不制造占位。

审批在时间线使用中性分组、橙色状态图标，同时进入全局待处理列表。分组展示原始动作与影响范围；上游实际提供的拒绝与允许选项并列可见，不通过折叠菜单隐藏拒绝操作。

输入框支持多行、文件引用和草稿。默认 Enter 发送、Shift+Enter 换行；中文输入法 composition 期间 Enter 不发送。首版运行中的新消息明确排队到下一轮，不向当前执行注入消息。高级输入设置属于后续实现。

### 3.3 变更检查区

文件列表带新增/修改/删除标记，选择后展示 diff；长路径允许中间省略并可查看完整路径。切换统一/并排 diff 只影响布局。没有采集证据时显示“工作区当前变更”，不标成 Agent 专属修改。

提交、合并和丢弃变更不属于首版主流程，避免在查看 diff 时出现隐式写操作。

## 4. 手机核心流程

手机底部入口为主机、会话、审批、设置；导航触达区域至少 44×44 CSS px，优先使用 48px。安全区、系统字体放大、软键盘和横屏都需验证。

会话列表按工作区分组，每行显示标题、Agent、运行状态和最后活动。点击进入单列时间线，顶部保留 Host 在线状态；输入区随键盘调整，不挡住最新消息。

审批详情是独立页：工作区 → 原始动作 → 参数/路径/diff → 状态与时间 → 底部动作。底部操作区使用 sticky 并预留安全区和内容间距；长命令可横向滚动，其余信息在 320px 下换行。批准按钮不默认获得键盘焦点，滑动或返回手势不能触发批准。

会话、详情、审批通过显式导航切换，不表示自动批准。点击决定后，立即显示提交中并禁用重复点击；成功后更新为结果页，冲突则显示其他设备的结果。

## 5. 插件管理与动态 UI

左侧是功能列表，右侧为详情，包含概览、配置、诊断；用户主要看到名称、用途、版本和状态。执行后端、generation、digest 收入诊断，不占据默认操作流程。

简单设置使用 Schema 表单，复杂交互允许 JS App 注册 React 面板、页面、命令和插槽；作者可用 TS 开发后构建为 JS。前端 SDK 统一管理注册和清理，并共享宿主 React 与主题变量。Schema 本身不执行任意表达式；代码型面板属于明确安装的可信模块。Host 对业务动作重新鉴权，secret 字段只返回“已配置”状态。手机仅加载兼容的浏览器 App 产物，不运行 Host 的 Node 或原生 Worker。

配置页有“未保存”提示和显式保存按钮，失败保留输入；更新失败保留旧版本并显示重试。禁用正在承载会话的插件时，展示受影响任务与“等待结束/停止任务”的具体选项，不一键误杀。

## 6. 视觉与组件规范

| 项目 | 当前规范 |
| --- | --- |
| 背景/表面 | 亮色 `#F3F3F1` / `#FFFFFF`；暗色 `#18191B` / `#202123` |
| 主文字/次文字 | 亮色 `#252622` / `#62645C`；暗色 `#E8E8E3` / `#A5A79F` |
| 主操作 | 亮色 `#30322C` 配白字；暗色 `#DEDFD6` 配深色字 |
| 待处理 | 亮色 `#8B5917`；暗色 `#DDBA79`，仅在状态、图标和必要提示使用 |
| 成功/错误 | 使用 success / danger 语义色，始终附状态文字 |
| 字体 | 系统中文无衬线；代码用系统等宽字体 |
| 正文字号 | 桌面 14–16px；手机输入与正文 16px；图内次级文字不低于 12px |
| 间距 | 4/8/12/16/24/32px；页面层级优先用留白表达 |
| 圆角 | 常规控件与工作分组 4–6px，工作台外框 7px |
| 控件高度 | 桌面常用 36px；触摸有效范围 ≥44px |
| 运动 | 状态反馈 120–180ms，尊重 reduced-motion |

语义色由 `prototype/src/theme.css` 统一维护。深色主题重新映射表面、文字、边界和状态色；图形 Logo 单独适配深色背景。右上角外观选择默认跟随系统，显式选择保存在本机，刷新后保留。跟随系统时实时响应系统外观变化；存储不可用时仍允许当前页面切换。主题在页面绘制前解析，减少启动时的亮暗闪烁。

## 7. 状态反馈矩阵

| 状态 | 页面反馈 | 可执行操作 |
| --- | --- | --- |
| 首次使用 | 添加工作区、选择 Agent 的引导 | 添加、探测、查看说明 |
| 加载中 | 保留布局的 skeleton，文字说明正在加载 | 可返回，不展示假记录 |
| 正在运行 | 状态标签、实时工具更新 | 支持时取消/追加 |
| 等待审批 | 卡片、收件箱数量、系统通知 | 在线查看并决定 |
| 提交中 | 当前按钮忙碌、禁用重复提交 | 其他只读区域可用 |
| 取消中 | 保留输出，显示正在停止 | 不提前标完成 |
| 断线 | 连接条与最后同步时间，只读快照 | 编辑本地草稿、重连 |
| 请求失效 | 失效原因，移除有效动作 | 返回当前会话 |
| 竞争冲突 | 展示已生效决定及处理设备 | 查看结果 |
| 投递不确定 | 说明决定已保存但回传未确认 | 查看诊断，等待新请求 |
| 插件更新失败 | 保留旧功能、错误原因 | 重试/查看诊断 |
| 无访问权限 | 明确权限不足，避免误显示“无数据” | 切换授权工作区 |

## 8. 无障碍与验收

- 所有按钮、输入、导航使用语义元素，图标按钮有可访问名称；Tab 顺序与视觉顺序一致，提供可见焦点。
- 屏幕阅读器低频宣布 Run/审批状态，不逐 token 朗读；重要失败使用 alert，普通状态使用 polite live region。
- 不以红绿颜色作为唯一提示；完成/等待/失败均有文字与不同图形标识。
- 检查 320/390/768/1024/1440/1920px、200% 缩放、长路径、长中文标题、空记录、大量工具输出与软键盘。
- 不要求 hover 才能发现主要动作；触摸下可展开原始内容与完整路径。
- SVG 具有 title/desc，文档同时提供文字流程；图示不能成为理解或操作的唯一入口。
