## 页面结构

设置使用左侧分类＋右侧内容的全宽页面，代替弹窗中再嵌套多层面板。原工作台可一键返回。页面共享已经确认的 Logo、系统字体、亮暗调色与控件；普通设置用一层分组容器、分隔行和行尾操作。多对象配置使用平面的列表＋详情区，不堆叠卡片。

| 分类 | 内容与操作 | 已有实现依据 |
| --- | --- | --- |
| 常规 | 主机连接、重新连接、接入入口、历史与执行规则、数据目录跳转 | 桌面连接页、会话与队列实现 |
| 外观 | 亮暗/系统、强调色、背景与前景、恢复默认 | 本轮已确认的外观原型；正式应用目前具备基础主题切换 |
| 通知 | 桌面通知请求与事件说明 | `notifications.js` 与 `Management.jsx` 的审批/执行结束通知入口 |
| Agent | 接入工具、入口与认证区分、配置类型/名称/启动路径/JSON 参数、修订、新建与移除 | `Management.jsx` 的 Profile 配置与 `main.jsx` 的 Provider 可用性；认证仍由本机工具管理 |
| 工作区 | 已关联目录、导入演示、托管项目路径、工作树执行互斥说明 | 工作区导入、托管项目与 Worktree 租约 |
| 插件 | 已安装、启停、当前代次、权限、安装/更新检查、配置 JSON、信任与范围 | `plugins.jsx` 的本地候选检查、安装、更新、停用与重新启用 |
| 远程连接 | HTTPS 开关、IP/端口、CA 导出、配对码、待确认设备、角色/范围、确认/拒绝/撤销 | `Remote.jsx` 的 HTTPS 入口与设备管理 |
| 数据与诊断 | 存储、主机空闲重启、脱敏诊断生成/复制、协议信息 | 连接页、`Management.jsx`、诊断允许列表 |

设置搜索按分类名称及关键词筛选，例如“配对”“主题”“配置”。直达页使用 `?view=settings&section=agents` 等参数，八个 section 为 `general`、`appearance`、`notifications`、`agents`、`workspaces`、`plugins`、`remote`、`data`。原 `?view=appearance` 入口继续打开外观页。

## 交互约定

- 启动入口可用不等于认证成功；不显示未经检查的账户状态，也不提供现有产品尚未实现的订阅与登录管理。
- Agent 配置校验绝对启动路径及字符串 JSON 参数数组；保存产生新修订，已有会话保留历史配置。
- 插件先检查目录与清单，再选择工作区范围、填写配置并确认信任，才能模拟安装；不实际加载代码。
- 手机入口是局域网或已有可信网络的 HTTPS 服务；证书导出与安装分开。配对码明确标为无效演示，不显示可误扫的假二维码。
- 设备需指定角色与非空工作区范围才能授权；授权、拒绝与撤销均可体验。
- 诊断只展示演示计数、版本与状态。重启模拟短暂进行中状态，实际实现中的执行中禁重启规则保留。
- 没有统一 Skill、MCP、自动化、账号订阅或扩展市场页面；这些不属于当前已完成的管理能力。会话专属 Agent 参数继续留在对应会话，而不是误当作全局配置。

已保存常规亮暗、Agent、插件与远程连接的截图。待审阅的是分类是否清楚、设置密度是否适合日常使用、Agent/插件的列表详情结构，以及全页设置与返回工作台的关系。用户批准后才重写正式设置界面，不直接把原型合并为生产代码。
